# Task 03: 商家端小程序开发

> **分支名：** `feat/supplier-miniapp`  
> **负责人：** 前端开发工程师（商家端）  
> **优先级：** P1

## 1. 任务目标

实现供应商（商家）使用的独立小程序，支持账号密码登录、查看平台派发的待发货订单、确认发货、查看历史订单。

## 3. 页面清单

### 3.1 登录页

**路径：** `/pages/login/index`

| 元素 | 说明 |
|------|------|
| 账号输入框 | 平台运营在后台创建的登录账号 |
| 密码输入框 | 支持显示/隐藏密码切换 |
| 登录按钮 | 调用 `POST /supplier/login`，成功后保存 JWT |
| 错误提示 | 账号或密码错误时 Toast 提示 |

**状态保持：**
- 登录成功后 JWT 存入 `Taro.setStorageSync('supplier_token', token)`
- 每次启动时检查 token 是否过期，未过期自动进入首页

### 3.2 首页 / 待处理订单列表

**路径：** `/pages/index/index`（作为首页默认展示）

| 元素 | 说明 |
|------|------|
| 顶部统计卡片 | 今日待发货订单数、累计已发货订单数 |
| 订单列表 | 平台派发给当前供应商的 `PENDING_SHIP` 状态订单 |
| 列表项字段 | 订单号、下单时间、商品总数、收货人、收货地址（脱敏显示） |
| 空状态 | 无待处理订单时显示"暂无待发货订单，休息一下吧" |
| 下拉刷新 | 支持下拉刷新列表 |

**交互：**
- 点击列表项进入订单详情页
- 列表按下单时间倒序排列

### 3.3 订单详情页

**路径：** `/pages/order/detail?id=:orderId`

| 元素 | 说明 |
|------|------|
| 订单信息 | 订单号、下单时间、状态标签（待发货） |
| 商品清单 | 商品名称、规格、数量、单价（不显示成本价） |
| 收货地址 | 收货人姓名、手机号、完整地址 |
| 发货操作区 | 快递单号输入框（选填）、"确认发货"按钮 |
| 备注 | 用户订单备注（如有） |

**交互：**
- 点击"确认发货"弹出二次确认弹窗
- 确认后调用 `PUT /supplier/orders/:id/ship`
- 发货成功后 Toast 提示"发货成功"，返回列表页并刷新

### 3.4 已发货订单列表

**路径：** `/pages/history/index`

| 元素 | 说明 |
|------|------|
| 列表 | 当前供应商已发货的历史订单 |
| 列表项字段 | 订单号、发货时间、商品总数、快递单号（如有） |
| 空状态 | 无历史订单时显示"暂无已发货订单" |
| 底部 Tab 切换 | "待处理" / "已发货" 切换 |

## 4. 关键实现规范

### 4.1 请求封装（与用户端独立）

```typescript
// apps/supplier/src/utils/request.ts
// 封装 Taro.request，统一注入 supplier_token
// 401 时跳转登录页
const request = (options) => {
  const token = Taro.getStorageSync('supplier_token')
  return Taro.request({
    ...options,
    header: { Authorization: `Bearer ${token}` }
  })
}
```

### 4.2 权限控制

- 所有页面（除登录页外）需检查 token，无 token 强制跳转登录页
- 供应商仅能看到自己被派发的订单，后端已做权限控制，前端做好空状态即可

### 4.3 地址脱敏

- 收货人姓名：显示为 `张*`（只显示姓）
- 手机号：显示为 `138****8888`
- 详细地址：完整显示（供应商发货需要）
