## 4. 关键交互实现规范

### 4.1 权限与菜单

```typescript
// 路由配置中标记权限
// 所有 /admin/* 路由需检查 JWT
// 401 时跳转 /login
// 菜单根据角色动态生成（超级管理员 vs 运营）
```

### 4.2 数据看板

- 使用 Ant Design Charts 的 `Column`、`Pie`、`Line` 组件
- 数据为实时查询（无缓存），因运营人员查看频率低
- 待处理提现数量用红色 Badge 醒目提示

### 4.3 商品图片上传

- 使用 Ant Design `Upload` 组件
- 上传前请求 `POST /upload/sign` 获取 COS 临时签名
- 直传腾讯云 COS，不走服务器
- 限制：主图最多 5 张，详情图最多 10 张，单张 < 5MB

### 4.4 Excel 导入

- 使用 `xlsx` 库解析前端上传的 Excel
- 解析后批量调用 `POST /admin/products`（逐条）或专用批量接口
- 导入结果反馈：成功 N 条，失败 N 条（附失败原因）

### 4.5 派单交互

- 订单列表中 `PENDING_DISPATCH` 状态的行显示"派单"按钮
- 点击弹出 Modal：选择供应商下拉框（从 `/admin/suppliers` 获取列表）
- 支持"一键自动派单"：调用 `POST /admin/orders/auto-dispatch`，批量处理当前筛选出的待派单订单
- 派单成功后刷新列表，状态变为 `PENDING_SHIP`

### 4.6 发货跟踪

- 订单列表增加"发货状态"列：待发货 / 已发货（显示发货时间）
- 已发货订单显示供应商名称和发货时间

## 5. Mock 数据策略

在 `apps/admin/src/services/mock/` 下创建 Mock 数据，与后端 API 契约保持一致。

Ant Design Pro 自带 Mock 方案（Umi 的 `mock/` 目录），但本项目使用 Vite，建议：
- 方案 A：使用 `msw`（Mock Service Worker）拦截 Axios 请求
- 方案 B：在 API 层封装统一开关，`const USE_MOCK = import.meta.env.DEV`
